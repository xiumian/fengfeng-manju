# Storyboard Prompter v2.9

把文本转换为两层可执行结果：

1. **九宫格分镜层**：3×3 分镜页，用于分析、审阅、出图和锁定连续性。
2. **视频生成层**：把九宫格镜头映射为 OG、通用逐镜提示词或 Seedance 2.x 表演提示词。

不要把九宫格当作九个任意画面。每格必须能追溯到剧情单元、表演节拍或必要的非剧情增量镜头。

## 最高准则

1. 剧情原文和台词优先于镜头美感。
2. 每个剧情单元至少被一个镜头覆盖；覆盖率必须为 100%。
3. 可增加建立镜、反应镜、细节镜和过渡镜，但不得新增事件、关系、道具用途或剧情结果。
4. 台词只能按原文引用或截断分配，不得同义改写。
5. 站位、朝向、视线、道具、服装状态、场景状态和主光方向必须连续。
6. 表演转译可以补充原文未逐字写出的可见微动作，但必须由文本情境触发、保持克制，并标记为 `表演转译`，不得改变剧情事实。
7. 一镜只安排 1–2 个主要动作；一个镜头只使用一种主运镜。
8. 所有推断必须与剧本事实、素材事实分开记录。

## 输入与权威层级

按以下优先级处理冲突：

```text
剧本原文/台词
  > SSPKG 场景空间数据包
  > 已确认的角色/场景/道具素材
  > lighting-consistency
  > blocking diagram
  > 用户确认的补充
  > 自建推断
```

支持：

- 剧本、小说、对白、场景描述
- SSPKG、调度图、光影系统、资产状态表
- 角色图、场景图、道具图
- 动作、运镜、风格、音频参考
- 既有视频的续写或局部编辑说明

## 统一数据模型

使用稳定 ID，禁止在流程中改名：

| ID | 含义 |
|---|---|
| `S01` | 场景 |
| `U001` | 剧情单元 |
| `D001` | 台词单元 |
| `P001` | 表演/情绪节拍 |
| `A001` | 动作或打斗节拍 |
| `T00` | 站位与状态快照 |
| `SH001` | 镜头 |
| `G01-P01` | 九宫页 01 的第 1 格 |
| `SG01` | 台词或固定镜头拆分组 |
| `OG01` | 视频输出组 |

每个镜头至少关联一个 `U/P/A/D` 来源 ID，并继承一个起始 `T` 快照和一个结束 `T` 快照。

## 工作流

### Step 1：输入确认与事实分层

输出四类信息：

```text
script_confirmed：原文明确的角色、动作、台词、情绪、道具、场景
asset_confirmed：素材可见的人物外观、场景布局、道具形态、光源
assumptions：为分镜可执行性所作的可撤销推断
missing_decisions：会显著改变空间、表演或镜头的缺失信息
```

多角色分配稳定 ID `A/B/C`，同时保留剧本名字。资产外观只进入资产/连续性表，不在每个画面提示里重复堆叠。

### Step 2：文本分析与剧情单元化

按原文顺序拆分：

- 独立动作
- 位置或朝向变化
- 视线变化
- 关键反应
- 台词、OS、VO、系统声音
- 道具状态变化
- 场景或时间变化

示例：

```text
原文：A推门进来，看见桌上的信，笑意停住。B没有回头：“你终于来了。”

U001 A推门进来
U002 A看见桌上的信
P001 A的原有笑意被“看见信”触发而中断
U003 B没有回头
D001 B说“你终于来了”
```

不把“看见信”和“笑意停住”合成含糊的“他很震惊”。

### Step 3：建立空间与连续性状态

从 SSPKG/素材读取；仅有文本时执行最小推断：

1. 建立 `T00`：人物位置、朝向、视线、姿态、道具持有。
2. 建立场景锚点：入口、出口、固定家具、关键道具、主光源。
3. 建立 180° 轴线。
4. 每次走位、道具转移、损伤、换装或场景破坏后生成新 `T` 快照。
5. 标注推断值，不把默认室内灯、月光、家具或坐标写成剧本事实。

连续性公式：

```text
SH-N.end_state = SH-(N+1).start_state
G-N-P09.end_state = G-(N+1)-P01.start_state
OG-N.end_state = OG-(N+1).start_state
```

### Step 4：提取表演节拍

对每个有意义的反应提取：

```text
baseline -> trigger -> involuntary leak -> controlled response -> end state
```

每个短节拍只选 2–4 个可见通道：

- 视线/眼神
- 眼睑/眉部
- 嘴角/下颌
- 呼吸/吞咽
- 肩膀/躯干/姿态
- 手指/握力/道具接触

约束：

- 原文明写的五官动作标记 `剧本确认`。
- 从情境推导的微动作标记 `表演转译`。
- 不把微表情当心理诊断。
- 隐藏注意力时先动眼再动头。
- 犹豫、受伤、害怕或克制时先写呼吸再写台词。
- 沉默听者或旁观者在剧情需要时只给一个有限反应。
- 微表情需要 MCU/CU 或可读的中景，避免忙乱运镜。

### Step 5：提取动作与打斗节拍

每次攻击、阻挡、摔落或能量命中拆成：

```text
意图 -> 起势 -> 发力路径 -> 接触点 -> 受力反应 -> 恢复/失衡终态
```

必须写明：

- 攻击者、目标和屏幕方向
- 起始与结束站位
- 武器/肢体/能量路径
- 接触点与发生顺序
- 防守或受击方向
- 环境接触反馈
- 最终姿态、视线和道具状态

不得让受击者逆着力线运动，不得在同一镜头堆叠未拆分的复杂连招。

### Step 6：生成镜头候选

每个镜头记录：

```text
shot_id
source_ids
duration
shot_size
angle
one_camera_move
start_state
visible_action
performance
dialogue_audio
end_state
continuity_constraints
```

镜头选择必须服务剧情：

- 建立空间：WS/FS
- 对话：双人 MS、OTS、CU、反应镜
- 微表情：MCU/CU，固定或缓推
- 动作接触：稳定 MS/FS
- 权力或尺度变化：有动机的高/低角度
- 道具因果：ECU

固定镜头 3 秒规则只作为“快节奏竖屏短剧”配置，不是模型硬限制。微表情、长对话或情绪连续性需要时，可使用 3–5 秒固定/极缓推镜头，但必须说明原因。

### Step 7：组织九宫格分镜页

读取 `nine-grid-workflow.md` 并执行：

- 每页固定为 `Gxx-P01` 到 `Gxx-P09`，按左上到右下排列。
- 默认一页不混合不同场景；场景切换优先新开一页。
- 镜头多于 9 个时顺序分页。
- 镜头少于 9 个时，只能补充不改变剧情的建立、反应、细节或过渡覆盖。
- 若没有合法补充镜头，保留 `RESERVED` 格，不虚构剧情。
- 九宫页内必须保持人物身份、轴线、站位、道具、服装状态、场景状态和光源连续。
- 每格必须列出来源 ID、起止状态和生成提示。

默认九格节奏只是建议：

```text
第一行：建立 / 基线 / 触发
第二行：发展 / 接触 / 反应
第三行：结果 / 恢复 / 转场
```

不得为满足行功能而改变原剧情。

### Step 8：映射到 OG 与生成提示词

九宫格是分析与分镜层，OG 是视频生成层。两者不要混为一个编号体系。

- 按平台允许的时长和叙事完整性把连续镜头组成 `OG`。
- 一个 `SG` 不跨 `OG`。
- 一个动作的起势与接触尽量不跨 `OG`；必须跨组时重复终止态。
- 每个 OG 写清九宫格来源范围，例如 `来源：G01-P04～G02-P02`。
- 用户未指定平台时输出通用逐镜格式。
- 用户指定 Seedance/即梦时，读取更新后的 Seedance 参考，输出自然语言、多模态映射、表演、镜头、声音和针对性约束。

Seedance 参考映射必须逐项分工：

```text
@图片1：角色 A 身份和服装
@图片2：场景布局和主光方向
@视频1：动作节奏或运镜时机，不复制人物身份
@音频1：节拍或声音风格
```

不要宣称像素级锁脸、固定字符上限、保证 4K 或确定性运镜。时长、分辨率、素材数量和音频开关以当前界面/API为准。

### Step 9：一致性与覆盖审查

必须通过：

- 剧情单元覆盖率 100%
- 台词逐字、顺序不变
- 表演变化有触发，强度与景别匹配
- 表演转译未新增剧情
- 每个动作有起点、路径、接触和终点
- 受力方向正确
- 九宫格格号连续、来源可追溯
- 跨页、跨 OG 起止状态一致
- 站位、轴线、视线、道具、服装状态、场景状态、光源连续
- 每镜一种主运镜、1–2 个主要动作
- 声音与可见事件同步
- 负面约束短而具体，不与目标动作冲突

未通过时，先修复镜头或映射，不以“建议后期处理”替代。

## 默认输出

### 1. 来源确认

- 剧本事实
- 素材事实
- 推断
- 缺失决策

### 2. 文本分析账本

| ID | 原文 | 类型 | 角色 | 触发/因果 | 状态变化 |
|---|---|---|---|---|---|

### 3. 连续性状态表

| T 快照 | 人物位置/朝向 | 视线 | 道具 | 服装状态 | 场景状态 | 主光 |
|---|---|---|---|---|---|---|

### 4. 表演与动作节拍

| ID | 基线/意图 | 触发/起势 | 泄漏/路径 | 控制/接触 | 终态 |
|---|---|---|---|---|---|

### 5. 九宫格页

先输出九格总览表，再逐格输出完整提示。格式见 `nine-grid-workflow.md`。

### 6. OG / 平台提示词

按用户指定输出通用或 Seedance 格式，并标注对应九宫格来源。

### 7. 审查结果

列出覆盖率、台词、表演、动作、九宫格、连续性和平台约束结果。

## 最小逐格格式

```text
【格号】G01-P01 | SH001 | 来源 U001,P001 | 起始 T00 → 结束 T01
【景别·角度·主运镜】MCU | 平视 | 固定
【在场与空间】A 画面左侧面向右；B 画面右侧面向左；轴线不变
【画面】原文动作 + 可见表演 + 明确终态
【台词/声音】逐字台词；与动作同步的环境音或拟音
【连续性】身份、视线、道具、服装状态、场景状态、主光方向
【约束】只列当前镜头的高风险失败点
```

## 兼容性

保留 v2.8 的 SSPKG、BD、SG、OG、6 字段和 Seedance 输出能力。v2.9 新增的文本分析、表演转译和九宫格数据层位于逐镜生成之前，作为所有后续提示词的统一来源。
