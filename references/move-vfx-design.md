# 招式与特效：从视觉设计到正文保真

动作、特效、摄影、编译、复核共用此方法；普通动作只取适用部分，无特效不另造特效。招式库提供条件候选，不替代本场构造。以下是原创文本设计方法，未实测，不代表任一视频模型能精确执行。

## 先分能力事实与视觉空间

从原文/主人要求分清：谁发动、能力能做什么、对象与结果、必须保留的招式外形，以及授权内可设计的形态与过程。已指定的龙形、五层光轮、宽幅剑气、满屏粒子等是表达要求，不可偷偷缩成普通光球或几粒亮点。案例中的人物、配色、层数、蓄力与震动不自动成为默认；未授权的追踪、反伤、复制或毁城不能借外观补进来。

## 构造方法：六种关系，不是固定六段

在现有事件预算内，先找本招与前后招的视觉差异，再选择足以兑现它的关系。不是每招六项全填，不为流程另加蓄力/变身/爆炸；同一关系可跨镜，数种关系也可并行。

|关系|需要作出的设计选择|写不到位时怎样修|
|---|---|---|
|视觉身份|选可识别的轮廓、组织方式与运动性格：剑群是折扇展开后并束，还是分层回旋推进；雷是沿面爬行还是粗主干劈落|“金色史诗粒子”只有属性，补真正能看见的主形和变化，不只换颜色|
|内部层次|按本招选择骨架/实体主形、内流纹样、表面能量、外缘条带/电弧、离体碎晶；明确层间前后、连接、运动差别|不能只报“多层华丽光轮”；让选定各层有不同形态与相对运动。层数按本招，不统一五层，也不默认只准少量辅助|
|人物驱动|手腕、兵器、转身或位移如何触发方向与形态变化；离源前后谁仍控制什么|“挥剑，剑海攻击”缺接口；说明挥刃扫开的平面如何引动剑群，不用人物停等特效播完|
|展开与攻击|交代主形如何出现/展开/变形，如何跨越距离、覆盖空间或围合目标；挑必要阶段，不重复生成|巨大不等于满屏近物；用已有地标、人物与传播前缘建立尺度，攻击途中对手仍按条件应对|
|碰撞变化|明确命中部位与形态变化：切开、压凹、绕流、分叉、壳体剥落等；粒子随哪条力向喷出，环境怎样迟后响应|不同招式不统一成“闪白+爆团”；爆炸需要时设计亮核、外翻层、冲击前缘与后续碎片的时序|
|残留与承接|区分持续发射与一次喷发，剑片/电弧/烟粉/实物各自运动与退场；写下一镜还继承什么|停源不齐灭，切镜不重播起招；破坏不随能量消失而复原|

粒子不仅是命中后的碎屑，也可组成龙体、羽翼、剑阵、光轮、流纹或变形介质。先定组织结构，再按[粒子专项](vfx-techniques.md)选择粒径、密度、路径、惯性、发光与寿命。丰富来自差异和联动，不是每层都用“高速、大量、猛烈”。允许多层同时强、短暂满屏和厚重遮挡，镜头链仍需交代触发与后果；不把持续可读误解为全部透明、永远稀疏。

## 专业交接：提出需求不等于替对方定方案

仍用现有 design 的 event_id→文字，不增必填表格。关键招式在负责工序记录适用的视觉关系、先后/并行节点、跨镜持续状态与不能被概括掉的看点；用事件ID指向交接，不另建一套剧情。

- **action→vfx**：交发动者手位/兵器路径、发力与位移、对手应对、接触/胜负事实、时间容量；可提出“横扫须有横向铺展的招式”，不替特效锁定材质和层次。
- **vfx→camera/compile**：落实主形、各层运动、动作响应、攻击/碰撞变化和残留，指出“需看清外层展开与内层汇束”等观看需求；不擅定机位与切点。vfx设计引用action的触发节点，不重复另排攻防。
- **camera→compile**：把观看需求落到具体景别/方位/运动/切点；规模、局部结构、接触和反应可分镜展示，不要求一镜全包。切走后源、前缘和残留仍在既定位置推进。
- **冲突返修**：若动作给横扫而特效沿垂直轴坠落、或细层变化无法在给定景别/时长辨认，摄影指出具体缺口，退责任工序重排路径/层次/揭示。涉及既定事件预算回底稿；不默删视觉看点，不绕过失效机制直接改上游design。

简单局部反馈可以一句完成。复杂招式的关键看点按下面的“观看内容与兑现证据”在底稿和上游design中明确；后工序发现缺设计时返修，不由编译临场补招。只写“主形/层次/路径”三个标题不构成交接。

## 先设计观看内容，再分配时间

适用于主人强调视觉丰富、展开过程或有明确复杂主招式的场面。先读具体参考/需求，辨别要保留的是形态、铺展、浓密程度、变化机制还是冲击效果；没有看到参考原文就不声称已提炼。对每个被选为观看重点的招式，在现有creation或设计文字中先回答：**变化前是什么 → 哪个动作/能量运动驱动改变 → 哪些层怎样联动 → 变化后形成什么可见状态 → 对手/环境因此怎样回应**。这是推导关系，不要求拆成五个镜头，不给每招补一遍蓄力。成形可在追击或受压中完成，已持续存在的状态不重新生成。

**层间联动**不是“躯干、外壳、雷纹、雾带”的清单。例如：粗雷先分出脊线与双臂方向，暗雾沿其向躯干压实，外壳从肋侧贴合到肩部；抬臂时壳片沿肘缝错开，内流灌向掌心，外缘雾带滞后翻卷。各层有相对位置、驱动、速度差和新状态，才从构件变成正在发生的招式。也可以选择完全不同的形成机制；并非每个法相都必须用雷、壳和雾。

然后分配观看任务：哪项需先建立，哪项持续跨镜，哪项只在峰值看一下；摄影再安排时间与切点。**不能先排满固定镜长，最后把复杂主招式压成一行特效摘要。**稳定结构可以在全局集中定义，但全局描述不能替代时间轴里的形成、展开、攻击及状态变化；反过来也不在每镜复述全部材质。

时间紧时，先去掉自选重复攻防/同质爆发/重复起势，或让已成立的动作与变化并行，把观看空间给本场主看点。不能为了“数量都在”而把每个主招式都写成一闪而过。若次要招式是自选内容，可缩减其展示或在授权内减少数量；若主人锁定招式、剧情、时长或切点，不能擅删，须说明具体容量冲突并给可选重排/分段。**新增对白**、参考要求或情绪反应后，重新检查发声、口型、表情与特效揭示的观看竞争，不能原样复制镜头再往里加台词，也不能把所有特效观看点移到说话者脸后。

## 观看内容与兑现证据：用现有需求，不另造评分表

选定的关键视觉变化作为可核对的表达要求，不只记录“使用了某VFX-ID”。创作准备在已授权设计的补充来源里保存这些内容，以现有requirements登记到关联事件；保留原事实来源，不冒充主人逐句指定。普通小招不强制额外建需求，不设字数、层数、粒子数、镜数或通过率配额。多个独立看点不可全部塞进一个“特效丰富”的需求，再引用一句话宣布都完成。

例如：来源C1已有“剑列先展成扇面再折入中轴，首股碎裂后股继续”的授权设计，可登记：

```json
{"id":"R:fan","kind":"vfx","source_ids":["C1"],"event_ids":["E1"],"description":"剑列先展成扇面再折入中轴，须有展开到收束的变化，不只有扇面终态"}
```

分波受阻若也是关键看点，另登记对应需求。名称/颜色/宽度/密度若被主人明确指定，也按实质要求保护。source核对来源、固定项与授权补充；vfx提供能兑现该关系的具体设计；camera指出它在什么观察条件下可辨；compile的coverage给最终正文真实引句，跨镜过程可引用覆盖先后的片段；validate对照要求、上游和正文逐项判断，不只复用通用“已核对”理由。引句存在仅证明定位，不证明关系成立。

已开始生产后，原来源已有但漏登记的看点按discover补调；尚无来源的新增设计不能伪造source_quote，需按已有创作授权保存补充来源和旧版，再重新init。改已有上游方案用repair使下游失效，不能直接改摄影或正文绕过返修。

**拒收条件**：必需的展开变化在设计或正文里只剩名称/层名/最终姿态，即使来源、命中、消散、时码全齐，也标该项unmet，定位缺的是设计、取景还是编译。不得提交content_checked=true；现有接口只接收通过稿，失败细项留后台并走repair，不把失败结论伪填成通过。修后再提交新context回执。纯文字程序不能声称程序识别了空泛表达；语义拒收由执行者对照，自动检查只约束登记、引文、状态与交接。

具体的“只有层名/有联动但拍不到/加入对白超载/普通小招”对照见[兑现案例](visual-fulfillment-examples.md)，在调试表现不足时读取，不默认向所有专业加载整份案例。

## 编译保真：合并措辞，不合并不同信息

编译把“上游已定特征→最终正文引句/时段”短记在现有工序记录，按需复用coverage位置；不新增投喂栏目，不要求每个粒子独立ID。稳定外形集中全局，事件中的展开、变形、接触和残留写在发生处。全局列过“剑海”不能代替本镜剑群运动。

可以删除同义重复、合并同一触发的表述；不可把“宽幅弧刃中密集剑形沿切向排列、外缘条带滞后翻卷”缩成“绚丽剑气”。主形结构、层间运动和触发次序是不同信息，不是可删修饰。若正文缺失上游设计，修compile；若上游本来只有名称，返action/vfx；若拍不到，返camera。不以文笔流畅、全文变长或关键词存在作为保真证明。

## 表现力复核：引用差异，不给空泛分数

使用现有 evidence、requirement_reviews、limitations，按相关事件引用专业设计及最终正文，说明以下适用问题；普通小招无需全项报告：

1. 去掉招式名和颜色，仍能辨认它与相邻招的形状/组织/运动差异吗？若不能，指出缺的是哪种差异；同一招有意复用可成立，不强制每击换花样。
2. 粒子是否真正构成主形/纹样/流动过程，而非句尾装饰？关键层次在正文和所选镜头中能否分别体现？
3. 人物动作、招式展开、对手应对与碰撞是否相互驱动，而非四段互不相关的演出？
4. 编译是否丢掉已确认的宽度、密度、具体结构、变形、运动或结果？拒绝仅凭“有写特效”判通过。
5. 观看容量是否成立？0.5秒可抓已建立关系中的裂纹或打点，不承包陌生五层结构的完整揭示。超载先协调预算/切点/并行或删重复，必要要求仍放不下就报告冲突，不偷减配或把一切无限加速。

缺设计/丢细节/拍不到/容量冲突分别标明责任模块、event_id、原句、正文位置与fix_scope，沿repair返修。结构测试只证明规则和交接；语义由执行者实际对照。没有生成并观察视频，不能写“已保证炫酷/稳定成功”。

## 三种对照：看点怎么落实，而不是堆术语

### 万剑：从名词到组织运动
**不足稿**：“万剑归宗，金色剑海压向敌人，粒子满屏。”

**合格方向**（前提：已允许引导剑群且对手以护幕阻挡）：人物横引剑锋，近处剑影沿刃扫开的平面翻正，后方剑列逐层展开成宽阔扇面；手腕转向时，扇缘先折入中轴，数股剑流错层并进。首股撞上护幕后碎成薄片，后股穿过尚未熄灭的碎刃继续压入，幕面从接点向后鼓陷。摄影可先展示扇面与人物的尺度，再借动作匹配看接触，不把所有变化压成一次远景闪光。

不可借此新增自动追踪或必然破盾；若已定结果仅阻挡，保留幕体。正文有“万剑”而无扇面、汇束、分波和受阻差异，仍是丢设计。

### 旋枪：形态与动作一起形成
**不足稿**：“旋枪召唤粒子巨龙，横扫爆炸。”

**合格方向**（前提：已允许枪势生成龙形并击退目标）：枪头旋出的环带向前拉长为龙躯，粗密的暗色粒流维持头颈与脊线，外缘红色长丝沿盘旋方向滞后甩出；横扫时龙首先转、躯干顺枪势解旋扑出。撞击使头部粒流沿目标表面分开，尾部继续灌入，目标沿既定方向退开。环境碎石只在原已授权破坏处发生。人物动作不为凝龙暂停，具体命中仍承接动作设计。

### 护层：普通小招不被复杂化
**不足稿**：“华丽多层护盾迸发大量粒子。”

**合格方向**（前提：只需挡住一次冲击）：来袭压凹护层，受压点向外推开一圈短促流纹，边缘数片碎亮脱落后熄灭，护层与人物支撑仍在。若此处看点就是短促承压，不强加龙凤、五层结构或大爆炸；朴素不等于缺设计。

以上对照是原创方案示例，不复制参考附件的角色设定、不继承其矛盾指令，也不是生成模型已验证模板。
