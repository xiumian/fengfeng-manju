# 专业职责与交接边界
六项前置创作归属：剧情/新对白在创作准备定清后由source核对；人物道具、空间和美术实体/光源条件由assets；vfx承接能量形态及发光；camera落实观看、成像与光色组织；performance/sound落实既定对白与关系表达。详细入口在[创作准备](creation-preparation.md)，编译/复核保留具体设计，不把职责分开误当互不响应。
声音层次、材料/机制时序和前台保真统一见[分层音效方法](layered-sound-design.md)；动作/特效交触发需求，声音定听觉方案，摄影不暗改声源，编译不删层。

各模块围绕同一底稿协作，不各写一套剧情。原文、已确认事实与创作授权先由[创作准备](creation-preparation.md)和[底稿契约](project-contract.md)锁定。设计统一写在本模块的 design 命名空间。

## 创作决策顺序

以下是各工序共用的创作推导顺序，不调整source到validate的调用顺序，也不是给视频模型的栏目：

1. **主人要求与已定剧情**：先锁定当次时长、风格、格式、指定拍法、对白、关键事件和结果；授权内设计，不为表现力改掉固定事实。
2. **戏剧目的**：确定本场希望观众经历什么，以及由哪个事件、人物选择和结果支撑。紧张、痛快或牵挂不是只写一个情绪词；日常或氛围戏也不强加冲突反转。
3. **观看重点**：沿信息或局势变化判断，每个关键节点要看清什么、跟随谁、知道多少，以及哪些信息必须并存、哪些可以依次揭示；不按专业清单平均分配注意力。
4. **视听方案**：各专业在本职责内主动构造动作、表演、摄影、特效与声音，并交接必要关系。关键转折比较合理选项能获得和损失的信息，再落实所选方案；简单节点直接完成，不强制多套方案或分析表。镜头数量和运动方式是选择的结果，不是预设目标。
5. **可执行性**：核对时间容量、空间、支撑、接触、观察条件及状态承接；条件贯穿设计，不是到最后才允许发现不可行。发现冲突先修具体路径、机位、切点或节拍，必要时退责任工序；不默认删细节、减少切镜、让人物等待或弱化关键效果。固定要求无法兼容时明确冲突，不静默牺牲剧情。
6. **防漏交付**：编译融合已定设计，后台逐项反查来源、专业结果和最终正文，修遗漏与矛盾，不把检查清单写进投喂稿。程序交接通过不证明表达充分或成片质量。

连续性是要实现的条件，不是少切镜的理由本身。可用连续调度，也可用动作/视线匹配、方向与声桥承接；既不默认少切更稳或长镜更高级，也不把镜头多、运动多当表现力。测试稿同样先完成作品表达，再据此观察测试点，不让“便于检查”取代观看设计。必要取舍短记现有design即可，不新增必填字段；未实际比较就不事后声称已权衡多种方案。

| 模块 | 本模块决定 | 交给其他专业的需求，不代替其决定 |
|---|---|---|
| 资产 | 身份/形制/状态适配、候选与实际参考职责 | 状态冲突反馈底稿；取景需求交摄影，不用换资产偷偷改人物 |
| 动作 | 行动路径、攻防、接触受力、前后状态及动作节拍 | 标出必须看清的接触/结果与时间需要；特效外观交特效，机位/景别/运镜交摄影 |
| 表演 | 目标与触发、可见反应、情绪时序和后续行动 | 提出观众需读到的细节与反应时间；景别/切镜交摄影，声源和声音承接交声音 |
| 特效 | 已授权能力的主形、材料、传播、反馈与结果继承 | 需露出的主体/接点、允许遮挡的时段交摄影；不改变动作既定命中与能力范围 |
| 声音 | 发声归属、对白/OS/VO、可听范围、声音时序与承接 | 需显示的说话者或听者关系交摄影；不改原句和发声次数，不另定人物反应 |
| 摄影 | 观看目标、机位、景别、运镜、切点及衔接 | 依上游节拍兑现观看需求；容量或可见性冲突退责任模块，不改剧情、接触结果或自行加慢放 |
| 编译 | 按当前格式组织完整正文及独立排期 | 沿用已完成设计，不暗中换动作/表演/镜头；缺项回调度，格式冲突明确记录 |
| 复核 | 逐需求找证据、判断落实与定位问题 | 问题交负责模块返修，不另写一套未经交接的设计 |

招式协作的具体交接、冲突返修和表现力证据统一见[联合设计方法](move-vfx-design.md)。专业边界不等于互不沟通：动作提出驱动和观看需求，特效回应具体结构，摄影落实观看；提出需求不等于替对方锁定方案，编译不临场补缺失招式。

跨专业交接写清事件ID、必须兑现的信息、先后/并行关系、进入和离开状态及尚未解决的冲突；可直接写在现有 design 文字中，不强制增加新的JSON字段。比如表演写“接信后短暂屏息，需让观众辨出这一变化”，摄影再决定近景、推近或其他适合当前场面的看法。

动作决定是否需要变速及触发/恢复节点，摄影选择如何观看，编译沿用；总时长仍按事件底稿约束。协同可提出建议，但建议不是已生效的其他模块方案。后工序发现漏专业用 discover；已执行方案冲突用 repair；改原文/事件事实需保存旧版并重新 init，不绕过来源与权限核对。返修后受影响下游必须重做。

程序只约束写入字段、顺序和版本，不能自动识别 design 文字是否越专业。语义边界由执行者和 validate 对照上游核对，不能用“字段合法”证明没有越权设计。

情绪协作按[全域方法](emotion-performance-design.md)：表演交表达策略/线索与必要条件，动作/声音/摄影各自在职责内回应；不是表演代定镜头、光色或配乐。
