# 来源工序
六项前置方法按创作准备判断适用性：本工序实际加载剧情/对白方法，核对补充来源、既定原句和可执行事件；其余视觉决定在globals/requirements明确交给assets/vfx/camera。发现底稿只有结论、关键条件没定义，退创作准备，不把source变成临场编剧。
已登记导演衔接时按[导演前置](../production-specialties/director-handoff/prepare.md)核对决定、角色已知线索、前段采用材料和下一段必须成立的事实。剧本、照片表面可见状态和实际动态／声音分别记，不把待生成方案说成已发生。
复杂视觉任务按同context的[关键视觉兑现](../move-vfx-design.md)核对底稿：指定主形/密度与已选形成变化是否有来源并登记requirements；原事实与授权设计分开。只有VFX-ID/层名而缺需要展开的过程，返回创作准备，不以来源字段齐全放行；用户固定剧情/时码不可为扩展特效擅删。
整理人物当时知道/感知的事实与已定行动，区分原有情绪依据和授权内表演补充；无对白不等于无表演需求。全域情绪方法由专业模块落实，不在源核对时擅添秘密关系或心理结论。
先核对context的source_units，为每个非空源文段落填写source_coverage，再逐事件检查所需专业。发现requirements漏项用discover登记；不能只核对事件ID就声称源文完整。
输入：完整来源、当前要求、事件底稿。输出checked_event_ids和source_coverage，覆盖本次scope中的每个事件。部门接力另交事件级design：谁因什么而行动、哪个反应改变局势、结尾怎样接下一拍。下游从这份可拍底稿继续，不从镜头和正文倒填。
核对原事实、对白/OS/VO、关键反应、结果、换场与起终状态。所有source_ids真实可解析；完整源文到事件的漏项仍需逐条核对，程序不自动识别。新增设计不能冒充原文。
时间分配要容纳对白、反应、受力、慢放和摄影。复杂任务需要来源映射；简单任务不强迫长表。必要内容冲突先重排自选部分，再明确缺口。
