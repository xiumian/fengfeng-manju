# 动作工序
使用资产已交接的部件、握持、路线和交互状态；衣物或物件妨碍行动时协调资产。把人物驱动、兵器路径、应对、接触和后效交给[招式联合设计](../move-vfx-design.md)，不代定特效材质。保留[表演所需的迟疑、控制和并行任务](../emotion-performance-design.md)，不让交锋暂停等拍脸。
按[整场预算](../scene-rhythm-planning.md)给已登记的接触、反应、对白与特效过程留时间；重排自选重复交锋时保留已定胜负。向摄影交[动作节点与可见条件](../shot-rhythm-planning.md)，向声音交[材质接触、落点和余势](../layered-sound-design.md)；不代定切镜或混音。
具体条件方案见[打斗编排库](../打斗编排库/索引.md)，遵循同context的调用规则；程序按当前事件自动装入最多2类全文及action_candidates，明确ACT-ID涉及更多类时完整交接指定类。候选用于目标、攻防与局势变化，不替代本模块判断，不把名称当动作，也不把库内例子冒充已验证的模型结果。
攻防需要看得出接触、受力、路线变化和下一拍机会时，启用[写实打斗专项](../production-specialties/realistic-fight/guide.md)；在真实来源的动作需求登记 realistic-fight，直出档按需手工读。以双方可见的转换、支撑、落空或材料响应为交接，不把实战步骤或来源模板编进提示词。
输出为design：事件ID→具体设计文字，仅写本模块领域；不可修改source/events或其他模块设计。必要问题带回调度，不用站稳、等待或删对白回避冲突。
输入事件、时间、空间和上游状态。方法见下文。
## 交锋构造：从局势推下一动作

先在内部读清双方当前位置、持物、支撑、距离、行动目标和能力边界；不用替主人新增流派或力量等级。把一个交锋看成“尝试改变局势—对方可用应对—局势留下新条件”，不是双方各打一套互不相关的招式。

1. **用目标选行动**：护送要争取通道或时间，夺物要改变持有关系，脱身要拉开追击条件，压制要限制可用路线。同样一拳不能默认都以击倒为结果。
2. **用距离与障碍删掉不成立选项**：尚未到接触距离就先处理进入/截线；长物件在窄处的转动受空间影响；支撑已失去就不能直接从稳定姿态发重招。奇幻例外按已授权驱动力写清，不用现实限制抹去能力。
3. **给应对者真实选项**：其可见信息、可移动方向、手脚和兵器当前阶段决定可挡、可让、可追还是只能承受；不能为主角招式漂亮而让其他人无故停住。未被镜头看见不等于不再行动。
4. **选留下变化的一次交互**：这次格挡把兵器带向哪里、绕侧是否抢到通道、落空是否露出转身空当。下一动作从这个末态继续，不重复回正起手。纯展示招式也要保住持手、路径和落点，不强造反转。
5. **分配节拍**：真正需要先后完成的进入、接触、利用机会不能压成同时；追击、受者退让和衣发/碎屑余势可在条件允许时并行。重点动作展开，重复自选交锋可概括，但必需的胜负因果与转移不可删。

### 条件、选择与代价
|局势|可选方向|要兑现及注意的代价|
|---|---|---|
|保护身后对象|截断接近路线、带对方偏离、争取撤离窗口|不能只顾追击而丢护送目标；窗口要说明谁因此能走|
|夺取已持道具|先限制对方的持物行动，再改变归属|不把碰手直接写成到手；转移和双方后续手位可判断|
|持续追退|利用路线、门口或高低差改变双方节奏|绕行增加距离/时间；环境原本不存在就不临时添墙救场|
|以少对多|让现有空间或时序限制同时接触人数|未接触者继续逼近/绕行，不排队等待，不凭空给主角全向防御|
|强弱悬殊或奇幻高速|突出已确认的速度/能力差如何改变机会|不强求势均力敌；留可判断的起终关系，不拿瞬移词遮掉必要路径|

### 护送对照与纠错
原创条件例：甲护送乙穿过已有窄门，丙从侧面逼近。只写“甲连击逼退丙、乙离开”没有护送因果。可展开为：甲侧移占住丙通往门口的路线，在一次接挡中把对方兵器带向门外侧；乙利用该空当越过门槛，甲借原来的转身后撤跟上。重点是通道与窗口，不必新加重伤、爆炸或多轮连招。若主人要求甲不能后退，就改找同一设定内其他动作方案，不偷偷改结果。

纠错：动作很多局势不变→检查每次交互的作用；只写主角招式→补对方在当时条件下的应对；接触后无反应→写已授权的阻挡/位移/持物变化；每招站稳→从余势继续；时间不够→重排自选动作或明确容量冲突，不能把乙的撤离删掉。

动作设计只交动作与观看需求，机位/切镜交摄影。主创用动作叙事与预演协作的思路见[依据F5/F6](../method-evidence.md)；上述局势推演及护送例为影视创作综合方法，不是现实搏斗指导或已验证的生成结果。

## 1. 设计顺序与时间预算
整场节奏先按同context的[共用方法](../scene-rhythm-planning.md)确定；本模块将压力/策略变化落实到交锋与时间容量，不把每段写成一次等长出招，不为起伏擅自改原强弱与结果。并行动作与必须先后分别交接给摄影；既定时段放不下时提出具体容量冲突。
沿用底稿锁定的目标、时长、剧情/对白与结果，确定动作看点并分配动作节拍。记录特效需要承接的触发/接触状态，以及摄影必须看清的动作信息与观看时间，不替特效决定外观，也不替摄影安排机位、景别与切镜。预算与设计可往返调整，不先写招式清单再套时间。执行方式模糊时，在已授权能力与结果内主动完成动作方案；涉及新增能力或剧情先回创作准备，在授权内补底稿并重新init，不在动作design里暗改事实。
把必须顺序完成的动作与可以并行的反馈分开：到达后才接触，破防后才利用机会；追击可伴随受者失衡，挥斩可伴随力量形成，尘屑、衣发余势可继续到下一动作。每段有主观看焦点，但一镜可以连续攻防，不限定招数。没有剧情意义的第三人守候、重复接挡和逐招回正不占时间。
秒数是成片观看时长；对白、慢放、停顿和必要摄影揭示计入。分配主要动作的进入、接触与结果时间，不要求各占独立阶段。容量不足先删自选重复动作、减少无作用展示或重排时间；必须事件仍放不下则说明冲突并提出延长/分段，不擅删用户剧情，不以无限速度或画外隐藏解决。


## 2. 连续攻防与力度

在决定攻守易位的那一镜，从对手仍能施加的压力写起，把主角的选择落实到同一个可见接点。例如盾手回顶，扇骨被压弯；执扇者不再硬推而把扇面侧过来，法相随她改向，裂口两边的刻纹才错开。盾变碎是结果，不能代替双方如何形成这个结果。若原戏只是瞬发即中，就写被打断的动作，不为凑来回添加反击。
为双方选择不同运动语言：优势距离、攻击路线、力量/惯性和恢复方式。每组交锋有进攻、对方应对和局面影响，不要求每击反转或双方势均力敌。脱身、抢夺、保护等目标决定路线；对手依视距、能力和前一拍状态行动，不能站着等主角表演。
下一动作来自上一动作留下的武器位置、余势、失衡或破绽。恢复可以同时转向或反击，必要换撑和落地仍有因果；不默认“准备—展示命中—补步—站稳—下一招”。真实位移建立压力，接挡只是临时关系，不冻结在交叉兵器或举手守阵姿势。
关键打点用突然进入、实际接触和明显防线/运动变化产生力度，余势传到衣物、碎片或地形；重打点不必血腥，也不每击都打飞。强摄影和声音强调已有撞击，不替代身体动作。奇幻爆发按已设计驱动力成立，检查不能把超人动作改成普通匀速演示。


## 3. 速度坡道：用动作事件触发变速
动作工序先确定关键变化和正常节奏。只有接触、形变或局面变化需要额外观看时间，且符合本场节奏时，才选快—慢—快。动作工序记录触发和恢复节点，摄影执行，编译沿用。正文直接描述高速进入的动作、触发慢放的接触事件、慢放期间的连续受力，以及恢复正常速度的事件与紧接结果；不用孤立的“速度坡道”术语或倍率串替代动作。普通衔接保持利落，不逐招慢放；用户明确指定其他节奏时优先遵循。

选择慢放时可写成：“攻击高速逼近；接触瞬间，画面迅速转入半速慢动作，持续约……秒，呈现……；当……发生时，立即恢复正常速度，人物沿原受力方向……。”倍率可作为补充，如“半速慢动作（×0.5）”；慢放观看时长按当前看点与总预算分配，×0.5和0.5秒不是所有攻击的固定参数。时间轴给出所在区间即可，不为同一变化叠加大量重复时码和内部控制标签。

慢放仍有运动：接触形变、头肩偏转、重心位移或护层压缩连续推进；恢复速度时继承这些运动，不先贴住目标停姿，再无因弹飞。人物“高速攻击／飞退”描述运动速度，“半速／恢复正常速度”描述画面时间；相机跟随速度另行表达。整镜慢放时人物、兵器、衣发及环境运动一起减速；局部时间特效须明确作用范围。

按需查阅的写法示例：“重斧高速砸向墨豆胸口。接触瞬间，画面迅速转入半速慢动作（×0.5），持续约0.5秒：胸前护层受压凹陷，肩背后弓，双脚开始离地。护层炸裂时，画面立即恢复正常速度，墨豆沿撞击方向猛烈倒飞，撞断木栏。”此为结合官方表达原则编写的方案，不是官方原文或已验证成片。

慢放占成片观看时长，须计入动作与对白预算；半速观看0.5秒约对应原速动作0.25秒。交付前检查每个设计的坡道都有触发、慢放内容、观看时长、恢复节点和连续结果。纯文本中的倍率、秒数是生成意图，不能保证模型精确执行；连续播放成片后核验，严格数值要求可用后期变速实现。不能把文字或九宫检视当作速度效果通过。

表达依据：[Runway官方提示指南](https://help.runwayml.com/hc/en-us/articles/39789879462419-Gen-4-Video-Prompting-Guide)强调直接的视觉与运动描述；[Seedance官方文档](https://docs.volcengine.com/docs/ark/seedance-2-5?lang=en)示例使用具体事件触发慢动作并接续碎裂、飞溅。由此采用事件驱动表达；不将这些来源解释为对任意模型精确倍率／时间控制的保证。
