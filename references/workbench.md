# 工作台与九宫流程 — fengfeng

## 使用
Python 3启动scripts/serve_workbench.py，服务127.0.0.1随机端口，打开nine-grid.html。提供--no-open与--port，Ctrl+C停止。不自动连接模型，不自动加载历史样本。

导入TXT/Markdown或粘贴有时间轴文本，网页解析事件；没有时间轴使用启发式估算并待确认。SEG上限默认0表示不擅自拆分，实际约束明确后填写。通过事件编辑器核对剧情和时间，通过全局编辑器设置风格/人物/场景/道具；网页不会凭空添加角色参考图。

九格分别映射完整事件。超过九事件合并代表性观察格，但全事件不丢。少于九事件设置进展检查点；规则生成的动作文本仍需人工设计为可拍静态状态。助手制作时应直接修改项目JSON使每格action成为具体瞬间，并保存完整事件body，不能要求静态图完成一串动作。

复制九宫生成Prompt交给实际imagegen；查看图片并检查等大3×3、身份、人数、空间、道具、光线与技能阶段。读实际尺寸，不承诺精确2048×1152；格图和板图以实际尺寸为准。标签可由图像生成或在画布外显示，无法稳定生成文字时不用缺字冒充剧情失败。

回填整板后点选格。可记录期望/实际/仅修改，生成一张替换图，并在网页按目标格裁切合成，其他格保持原样。实际替换取消完成，保留版本记录；全局变化要反查相关格/板，必要时重生整板。

事件编辑器保留完整剧情时间轴；修改格内容涉及事实时先同步事件，使用确认核对动作清除冲突，之后再重新检视与确认。调整格的画面不是改变事件时长；事件时长在事件编辑器更新。

保存项目JSON包含可编辑九格、事件和内嵌图像，浏览器IndexedDB仅作为便利缓存，定期保存文件。重新导入只接受本版本工作JSON，拒绝最终结果JSON。所有图片审核及时间核对后由主人按按钮明确确认；助手测试不得冒充主人确认。

结果输出JSON或离线HTML必须来源同一确认版本；包含亡灵视频正文、九宫图和独立映射表，不包含编辑控件、作图指令或未审核片段。指定提交范围通过review_scope数组记录，默认全项目范围。

## 生图事实传递与定点纠错
整板、单格及纠错统一使用core.panelPrompt的事实描述。表演与期望可见状态必须进入实际生图输入；实际偏差和仅修改只属于纠错输入，不作为新剧情。expected记录本格可观察状态，不能与源事件矛盾。
涉及持物时写角色自身左/右手；视角变化时另核对画面侧，不从画面左右倒推角色左右。涉及机关时写可见形状与接触方式，不用有歧义的物件名称代替。跨段核对前段末格与后段首格的身份、位置、持物、环境状态；需要进入内部时明确角色都已越过门槛，而不只写正在进入。
测试必须从实际工作JSON经gridPrompt输出，并保存送入模型的原文；手工绕开生成器的测试不能计端到端通过。文本传递测试只证明字段未丢，不证明模型成图正确。缺少可见状态需核对，不能以保持一致等泛化文案当作完成。

## 源能力补迁移
故事板读storyboard-contract.md；全局视频风格不直接控制分镜。工作台新增独立分镜画风、来源ID、角度、起止状态、表演来源/链编辑。实际图稿读取对白/音效；最终修订记录不再输出空数组。旧九宫工作JSON须显式migrate_legacy转换，导入后核对迁移时间与旧REF，TMP引用保持未解析，不能定稿。

源事件改变后semantics_pending置真，详细状态/表演链必须重新核对，不能仅刷新动作就沿用旧状态确认。state_snapshots提供T引用定义，source_units/role_schedule在生产计划完整保留；最终结果仅带本轮已确认格实际引用的状态定义。旧工程每段保留独立场景与人物设定，不把首段设定复制到所有段。

## 九宫修订与视频正文同步（v0.3.8）
修改格动作/运镜/景别/表演/起止状态时记录video_sync_pending。选择事件下拉框中本格实际对应事件，再点“同步本格到视频正文”：对照提示的格修订，填写该事件最终连续画面正文，保留原动作顺序；工具原子写回events.body，原台词、插入位置与时间不改。正文太短而无法容纳原对白位置时拒绝同步并保留原数据。同步不是自动语义改写；不能直接把后台快照、AU、REF或格号粘入正文。
若修改仅为静态检查图，不应影响视频，点“仅调整分镜，保留视频原稿”并填写具体原因，记录审计；这不是同意掩盖源剧情矛盾。未解决的pending格不能通过确认或最终导出。同步或保留后仍须核对全段并重新查看图片，不能当作成图已更新。九格不转成九个节点；多个格共享事件时应结合全事件写稿，不将每格说明机械叠加。
事件改稿刷新与旧自动提取值一致的镜头字段；人工覆盖的值保留，仍待复审。全局改稿更新明确继承旧全局的段级锚点，不自动替换原台词或正文的人名，所有段设待核对。版本回退重新标记待同步。

## 线标操作
在“逐格制作线标与成图核验”中由Codex准备JSON，保存本格计划；复制生图稿前全段预检。回填实际图后逐条记录ok/issue，用户明确接受的偏差才填accepted及reason。查看记录绑定图片版本，旧记录不能沿用到新图。一般由Codex准备和核查数据，不要求主人手工编写全部JSON。
