# 剧情与事件展开

## 设计方法

先分原文固定事实、允许设计的执行细节、获准新增情节。忠实改编不是重写动机；纯拍法不新增背叛、误会、死亡或隐情。只交剧本时到创作准备结束，不强制启动视频工程。方法由创作者执行，程序不自动编剧。

1. 从人物正在做的任务出发：目标对象在哪，为什么此刻必须行动，当前知道什么、还不知道什么。目标可为修好灯或把话说完，不强加生死危机。
2. 找任务与条件的摩擦：空间阻挡、时间窗口、物件状态、他人选择或信息不足。优先使用已有条件；新阻力须在创作授权内，不能为了转折突然新造敌人或能力。
3. 把事件写成“行动改变条件，条件推动下一选择”。能量更大、镜头更多不等于剧情推进。将尝试、对方/环境反馈、获得或失去的机会写清；失败、成功和不行动都有具体后果。
4. 用观众与人物的信息差选择揭示顺序：先看到问题再等人物察觉，或跟人物一起发现。不能把未知秘密写进角色反应；揭示顺序改变人物可知信息时，要协调表演与摄影。
5. 确定结束时与开头相比哪项真的改变：通道、归属、决定、理解或关系。转折可有可无，不固定起承转合镜数，不每段反杀。
6. 先落实必需因果和关键看点，再按整场/单镜方法安排时间。只有一句新决定不扩成十段身世；十五秒放不下多次转折，就在授权内减少自选重复，不把必需过程藏画外。

## 交接与正文兑现

新增情节先保存在creative_addition来源，并记录授权与固定项，再进入events；不能由后续专业临场编剧情。source核对原句/结果/因果及各事件所需模块；动作交执行，表演交意图与反应，资产交条件，摄影决定观众怎样得到信息。具体路线与机位由负责专业完成，底稿不硬写所有摄影。

用现有requirements保护关键因果，kind=plot；例如“钩中伞骨使落点偏离，确认船尾后才松手”，不能只登记“成功逃走”。compile把因果落实为可见变化，不输出幕后动机分析；validate引用触发与后续选择所在句，不凭结尾存在就算中间充分。缺因果返修创作准备，错原文退source，执行断裂退对应专业；改底稿需另存再init。

## 案例与选择

**追逐不足**：“她被追到桥边，跳下刚好有船接住。”船是结尾救场巧合。可用方向：已有船灯先在桥缝下出现，她听到断路警告后改看灯的行向，受拉时发现船尾仍在移动，主动弃伞追落点。若原文规定她不知道有船，不能加预先观察，应按原事实寻找可成立的执行路径或说明缺口。

**日常不足**：“父亲修灯，女儿感动。”没有可见的关系过程。已授权温情小场景可选方向：父亲够不到灯扣，女儿先把凳子扶稳，再把父亲找不到的小螺丝放到他手边，灯亮后二人继续收拾而非宣布亲情。若原文已有台词和结尾，保留，不用这个例子替换。

这些是原创设计方向，不是固定套路或已验证成片；充分性由任务目标而非冲突数、反转数或字数判断。
